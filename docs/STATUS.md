## Пробелы, требующие решения продукта/архитектуры (не просто "дописать код")

## Известные компромиссы в реализованном фото/голосовых сообщений (6.1/6.3)
- Опубликованные фото/голосовые чата (`chats/{chatId}/media/...`) устроены так же, как и фото профиля: файл становится публичным по неугадываемому URL после модерации/загрузки, а не ограничен участниками чата через Storage Rules. Более строгий вариант (правило Storage, читающее участников чата из Firestore через cross-service rules, либо подписанные URL с истечением срока) не был реализован, т.к. не может быть протестирован end-to-end без реального деплоя и устройства в этой среде — решение зафиксировано как осознанный компромисс, а не незамеченная дыра.
- Голосовые сообщения не проходят автомодерацию (см. §7.2 выше) — задокументированный пробел.
- Библиотека записи/воспроизведения (`react-native-audio-recorder-player@3.6.14`) помечена автором как deprecated в пользу Nitro-based `react-native-nitro-sound`; выбрана сознательно более старая версия без зависимости от `react-native-nitro-modules`, т.к. Nitro-модули требуют дополнительной нативной настройки, которую нельзя проверить без сборки на реальном устройстве.
- Собрано и проверено только через `tsc`/`eslint`/`jest` — реальной сборки на iOS/Android/сборки нативных модулей в этой среде не было (как и для всех предыдущих нативных зависимостей проекта).
