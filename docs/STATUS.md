## Известные компромиссы в реализованном фото/голосовых сообщений (6.1/6.3)
- Медиа чата (`chats/{chatId}/media/...`) читают только участники: правило Storage сверяет `request.auth.uid` с двумя uid, из которых состоит `chatId`, сообщение хранит путь, а клиент запрашивает download-URL сам. Остаточный момент: выданный Firebase download-URL содержит токен и работает у любого, кому этот URL передали, пока токен не отозван — то есть защита от «файл лежит публично по пути» есть, а от пересылки уже полученной ссылки нет. Полное закрытие потребовало бы подписанных URL с коротким сроком жизни (нужен сервис-аккаунт с правом подписи и проверка на реальном деплое).
- Голосовые сообщения не проходят автомодерацию содержимого (см. §7.2 выше) — задокументированный пробел. Тип файла (что это действительно аудио) при этом проверяется всегда, независимо от модерации контента.
- Библиотека записи/воспроизведения (`react-native-audio-recorder-player@3.6.14`) помечена автором как deprecated в пользу Nitro-based `react-native-nitro-sound`; выбрана сознательно более старая версия без зависимости от `react-native-nitro-modules`, т.к. Nitro-модули требуют дополнительной нативной настройки, которую нельзя проверить без сборки на реальном устройстве.
- Собрано и проверено только через `tsc`/`eslint`/`jest` — реальной сборки на iOS/Android/сборки нативных модулей в этой среде не было (как и для всех предыдущих нативных зависимостей проекта).
- Отменённая короткая запись (<1 сек) не удаляет локальный временный файл на устройстве — не стали добавлять новую зависимость (`react-native-fs` или аналог) ради этого: файл лежит в кэш/temp-директории ОС, которую система очищает сама.

### Найдено security/code-ревью и исправлено в этом же проходе
- **Критично** — `sendChatMedia` доверял клиентскому полю `type` без проверки реального содержимого файла: `type: 'voice'` полностью обходил модерацию и позволял опубликовать любой файл (до 15 МБ) под публичным URL приложения. Исправлено: content-type файла (`getMetadata().contentType`) теперь всегда сверяется с заявленным `type` (`image/*` / `audio/*`) до публикации.
- **Критично** — авто-остановка записи по лимиту 300с (`useChatVoiceRecorder`) останавливала нативный рекордер напрямую, не проводя её через `stopAndSendRecording` — React-состояние `isRecording` расходилось с реальным состоянием, что ломало отправку и вешало экран. Исправлено через `ref` на актуальную `stopAndSendRecording`.
- **Критично** — ни `useChatVoiceRecorder`, ни `useVoicePlayback` не останавливали запись/воспроизведение при размонтировании экрана (уход из чата во время записи/прослушивания оставлял активным микрофон/аудио). Добавлены cleanup-эффекты.
- **Критично** — правило `chats/{chatId}/pending/{uid}/{fileName}` (и уже существовавшее `users/{uid}/pending/{fileName}`) использовало `request.resource.size` в общем условии `allow read, write` — это поле не определено для чтения. Разделено на отдельные `allow read`/`allow write`.
- **Важно** — при падении Firestore-транзакции в `sendChatMedia` уже опубликованный файл не удалялся (утечка публичного файла без ссылающегося сообщения). Добавлен откат по аналогии с `submitProfilePhoto`.
- **Важно** — повторный/гоночный вызов `sendChatMedia` с тем же `pendingPath` падал необработанным исключением Storage SDK на `.move()`. Обёрнуто в понятный `HttpsError`.
- **Важно** — `useVoicePlayback.toggle()` мог зареджектиться (битый/недоступный URL) без обработки — необработанный reject промиса. Добавлен `.catch()` в месте вызова.
- **Важно** — клиент вызывал `markChatRead` на каждое своё же отправленное сообщение, хотя `readBy` отправителя уже проставляется сервером в той же транзакции — лишний вызов Cloud Function на каждое исходящее сообщение. Пропускается, если последнее сообщение — моё.
- **Важно** — на `sendChatMedia` не было rate limit. Добавлен дневной лимит (`mediaMessagesUsedToday`/`mediaMessagesResetAt`, 30/день, серверный сброс по UTC-полуночи — переиспользован и обобщён `functions/src/shared/dateUtils.ts`, ранее `swipes/dateUtils.ts`).
- **Незначительно** — гонка при быстром двойном тапе "отменить"/"отправить" в `useChatVoiceRecorder` (оба читали устаревшее `isRecording`). Добавлен guard `isStoppingRef`.
- **Незначительно** — `parseChatId.ts` неявно полагался на то, что uid не содержит `_`; задокументирован как явный инвариант (fail-closed, не эксплуатируемо).

### Проход по слабым местам ревью (приватность выдачи, медиа, случайность ленты, тесты)
- **Лента свайпов теперь строится на сервере** (`functions/src/feed`, callable `fetchSwipeCandidates`): фильтрация (свои свайпы, блокировки в обе стороны, `autoHidden`, взаимный фильтр по полу, возраст/теги/верификация) выполняется до отдачи, наружу уходит только `PublicProfile` — белый список полей. Клиентские копии `matchingRules.ts`, `candidateApi.ts` и `fetchSwipedTargetIds` удалены (логика переехала, а не продублирована), тесты перенесены в `functions/src/feed/eligibility.test.ts`.
- **Чтение `/users` ограничено**: свой документ, связанные пользователи (мэтч/дружба/чат — через детерминированный id пары) и заблокированные. Поиск по юзернейму — callable `lookupUserByUsername`, отдаёт `null` для авто-скрытых (7.3) и для заблокированных пар (6.2).
- **Круговой проход по `sortKey`** вместо однонаправленного — устранён системный перекос видимости анкет (4.2.1). Клиент останавливает подкачку по `nextCursor: null` и после трёх подряд пустых страниц, т.е. отфильтрованный «в ноль» пул больше не приводит к бесконечной череде вызовов.
- **Медиа чата приватное**: файл не публикуется, сообщение хранит путь, Storage Rules пускают только двух участников, клиент резолвит URL через `resolveChatMediaUrl` (с кэшем).
- **Исправлен баг правил**: `get` несуществующего документа в `/matches` и `/friends` отклонялся (условие обращалось к `resource.data`), ломая штатные проверки «уже есть мэтч/заявка» перед отправкой заявки в друзья и в шапке чата.
- **Исправлен баг авто-стопа голосовой записи**: длительность бралась из устаревшего замыкания, на границе лимита запись могла быть отброшена как слишком короткая. Значение продублировано в `ref`.
- **Тесты на хуки с побочными эффектами**: `useSwipeFeed`, `useVoicePlayback`, `useChatVoiceRecorder` (+ минимальный `renderHook` на `react-test-renderer` в `shared/lib/testing`). Прогнаны `tsc --noEmit`, `eslint`, `jest` в обоих пакетах — зелёные (63 теста в приложении, 59 в functions). Нативной сборки iOS/Android в этой среде по-прежнему не было.
